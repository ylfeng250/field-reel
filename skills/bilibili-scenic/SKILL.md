# 风景旁白

画面是主角，旁白是一个人坐在车上、站在山上，跟朋友讲这条路。先写一整段话，再往镜头上分；不要一个镜头憋一句。

脚本、方案页、闸门和渲染细节都在共用目录，先读 [skills/bilibili-cut-core/reference.md](skills/bilibili-cut-core/reference.md)，按里面的四步走。这份文件只写这一类片子特有的东西。写稿和取舍标准见 [style.md](style.md)。

## 写 analysis.json 之前

1. **认地方。** 从牌子、龙门架、路标、定位里认出这是哪条路、从哪到哪、多长、海拔。只用画面上看得到的、定位算得出的，或者用户说过的。要用外面查来的事实（比如「这里曾经是一片湖」），在 `note` 里标「待你确认」。
2. **挑镜头。** 同一个机位、同一种车窗只留最好的一段。先按 [style.md](style.md) 的时长目标挑，挑完再写稿。
3. **找配乐。** 风景片的情绪一大半靠音乐，写稿前就定方向。按 [style.md](style.md) 去能投稿的曲库找两三首不同情绪的候选，下载到 `$DIR/board/music/`，写进 `music_options`（`title`、`credit` 署名原文、`note` 一句风格）。下不到就留空，告诉用户自己放一首进 `board/music/` 再重建页面。
4. **写旁白。** 按 [style.md](style.md) 先写一整段，自己从头读一遍，顺了再拆到镜头上。

## 写 analysis.json 时

- `style` 填 `scenic`。
- 旁白拆进每段的 `subtitle`，一句一行。一个镜头放不下的句子，宁可把镜头留长，也不要硬拆半句。
- 车里的歌、路人说话不算口播，`speech` 清空。他自己真说了、又好听的一句（「这个河谷好漂亮啊」）可以保留原声，那段 `subtitle` 写原话。
- 每隔几段留一个不写字的镜头，让画面和音乐自己走。
- `beats` 按地貌或路段分：「出发」「河谷」「山梁」「林子」「草原」「到达」。
- 有定位的公路、骑行、徒步线，默认提议路线图。先出样图：

  ```bash
  python3 skills/bilibili-cut-core/scripts/route_map.py "$DIR" "路线名" "起点" "终点" 0
  ```

  打印出的图片路径写进 `map_samples`，路线名、起终点、公里数写进 `map`。公里数用牌子上的，没有就写 0，按定位算。
- 默认预填 `transition: "black"`、`field_volume: 0.3`。用户可以在页面上改。

## 页面上要提醒他的

- 「旁白连起来读」那一栏是整段旁白。读着不顺就直接在各段里改字，那一栏会跟着变。
- 段落下面的红字是旁白比画面长，渲染会挪出点、放慢或定格。删几个字最干净。
- 配乐可以直接在页面上试听。

## 确认之后

风景片第一次出片前先跑一遍 `--preview`，告诉他预览路径，重点听配乐大小、看旁白节奏。他说可以再出成片。之后只改了字或配乐，直接出成片，没改的段会走缓存。
