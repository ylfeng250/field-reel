# 边走边说

一条视频只讲一条路（或一家店）。口播用他当场说的话，顺序默认跟拍摄时间走。先给方案，人在页面里改完，再剪。

脚本、方案页、闸门和渲染细节都在共用目录，先读 [skills/bilibili-cut-core/reference.md](skills/bilibili-cut-core/reference.md)，按里面的四步走。这份文件只写这一类片子特有的东西。取舍和画面标准见 [style.md](style.md)。

## 判断是不是这一类

转写完看一眼：留下来的段里，一半以上有他清楚的口播，就是这一类。大半是风景、只有零星几句，或者只有车里的歌，转给 `bilibili-scenic`，并告诉用户为什么转。

## 写 analysis.json 时

- `style` 填 `walk`。
- 有原话的段，`subtitle` 用原话，只做断句和听写修正（同音字、漏字、地名）。不改他的说法，不补他没说的知识。
- 用 `voiced` 和 `speech_start`、`speech_end` 收紧进出点：说话前留约 0.6 秒，说完留约 0.8 秒。走路没说话的大段拖沓砍掉，但关键画面（牌子、岔路、日落、上菜）宁可多留两秒。
- 没说话、又值得留下的画面（定场、牌子、日落），按 [style.md](style.md) 写短旁白稿放进 `subtitle`，`speech` 留空。页面会让他选「只上字幕」或「自己念」。
- `beats` 按路线节点分，比如「出发」「上台阶」「岔路」「山顶」「下山」。探店就按「进门」「点单」「上菜」「结论」分。成片会用它生成章节时间点。
- 配乐默认不放。他要配乐，再按 [style.md](style.md) 找两三首候选放进 `music_options`。
- 有定位（`map_available` 为 `true`）、又是走一条完整线路的，可以提一句路线图，用 `route_map.py` 出样图放进 `map_samples`：

  ```bash
  python3 skills/bilibili-cut-core/scripts/route_map.py "$DIR" "路线名" "起点" "终点" 0
  ```

## 交付时

除了共用的交付清单，再说一句：哪些口播被删了，为什么删（重复、听不清、跑题）。他可能想捡回来。
